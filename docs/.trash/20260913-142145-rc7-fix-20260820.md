# rc.7 修复记录（2026-08-20）

> 版本：`0.1.0-rc.7.20260820b`（独立 appname `deepseek-harness-rc7`）
> 修复原因：初版 rc.7 fpk 安装后**污染主环境**（改写主环境 `.dsh/profiles/node_modules/` 下 510 个软链指向 rc.7），
> 本记录说明两个根因与修复方式，供打包/部署时参考。

## 一、根因 1：runner.js 硬切共享工作区

**问题**：`bin/runner.js` 中 WORKSPACE_DIR 逻辑：

```js
// 旧（错误）：
let WORKSPACE_DIR = VAR_DIR;
if (fs.existsSync('/vol1/@appshare/DeepSeekHarness')) {
    WORKSPACE_DIR = '/vol1/@appshare/DeepSeekHarness';  // ← 硬切到主环境共享区
}
```

rc.7 启动时 DSH_HOME/HOME 解析到共享区 `.dsh` → 引导 `healProfilesModuleFallback`
对**主环境** profiles/node_modules 逐个重建软链指向 rc.7 应用目录 → 主环境被污染。

**修复**：WORKSPACE_DIR 保持 VAR_DIR（本应用独立数据区），并**显式锁定 DSH_HOME**：

```js
// 新（修复）：
let WORKSPACE_DIR = VAR_DIR;
// spawn env 中：
DSH_HOME: path.join(WORKSPACE_DIR, '.dsh')  // 优先级最高的 DSH_HOME，铁定指向独立区
```

## 二、根因 2：fnOS config 的 data-share 共享

**问题**：`config/resource` 的 `data-share` 声明共享目录 `DeepSeekHarness` →
fnOS 安装器把 `/vol1/@appdata/<app>/data` 软链到主环境共享区 → 再次引导污染。

**修复**：`config/resource` 移除 `data-share` 段（仅保留 port-config + systemd-unit）。

## 三、验证结果

| 检查项 | 结果 |
|---|---|
| rc.7 数据隔离 | ✅ `DSH_HOME=/vol1/@appdata/deepseek-harness-rc7/.dsh` |
| 主环境软链污染 | ✅ 0（install 后复查） |
| 主环境 3081 | ✅ HTTP 200 正常 |
| rc.7 独立运行 | ✅ 3190(反代)/3191(内部) 200 |

## 四、部署注意（防再犯）

1. **新实例必须独立数据区**：runner.js 不要硬切共享区，spawn 时显式 `DSH_HOME`
2. **fpk config 不要带 data-share**：除非该应用确实需要共享目录
3. **安装后立即查**：`find <主环境>.dsh/profiles -type l | xargs readlink | grep -c <新app名>` 应为 0
