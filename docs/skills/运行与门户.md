# Skill：运行与门户（start.sh）

> 本文件承载 `start.sh` 与三端口的解释性内容。README 只给命令与端口表。

## 1. 服务生命周期

`start.sh {start|stop|restart|status}`。启动流程：解析实例目录 → 生成/读取端口 → 拉起 DSH（`dsh web`）→ 等待就绪 → 启动反代 → 从日志提取 token → 同步门户配置。

## 2. 实例定位（多布局自适应）

脚本按候选顺序探测实例根目录（`$DSH_HOME`、包内 `target/`、`@appdata` 下的用户目录等），并把结果写入名牌与门户。多布局共存时以"实际存在 `package.json` 的那一层"为准。

## 3. 品牌与版本名牌

网页左上角显示 `brand_name + 版本号`。取值链：`build-config.yaml` 的 `defaults` → 平台段覆盖（`spk:` / `fpk:`）；版本号优先级链由 `brand_version_order` 控制（`dsh` → `npm`），**不允许自定义**（永远同步官方源码 `package.json` 的 `version`）。

## 4. 反代：门户免密 + 局域网硬闸 + 直连 403

判定顺序（**改判定时必须同步 README 的门户章节**）：

```
⓪ 局域网硬闸      → 非局域网来源一律拒绝
① URL 自带 token  → 直接放行（门户入口正是这种）
② 已持 dsh-auth cookie → 放行（token 换 cookie 后 30 天内免密）
③ 门户打开        → 302 到带 token 的 URL
④ 地址栏直连      → 403 提示"请从套件图标打开"
```

**为什么门户 URL 无条件携带 token（2026-10-07 方案 A）**：早期用 `Sec-Fetch-Site` 区分"门户打开"与"地址栏直连"，但浏览器新开标签页（DSM 打开套件的方式）与地址栏手输**同为 `none`**，无法区分 → 门户打开被误判为直连而 403。现改为让门户入口 URL 自带当前 token，完全不依赖该请求头。

**token 轮换**：token 每次 DSH 启动都会变，故 `start.sh` 启动成功后调用 `sync_portal_token()` 把当次 token 写入门户配置的 `url` 字段；服务已在运行时也同步一次（无需重启即可刷新）。

**与安装期重写的兼容**：`pack-spk.sh` 的 `apply_wizard_ports()` 在安装期只改 `port` 字段（`sed` 精确匹配 `"port"`），不会冲掉运行期写入的 `url` 字段。

## 5. 容器页面（第三个端口）

除反代端口与 DSH 原生端口外，另有一个容器页端口（默认 3082），用于在同一套件内提供独立入口。

## 6. DSH_HOME 与插件安装

`start.sh` 在服务侧 export `DSH_HOME`，并提供 `dsh` 命令 wrapper，使插件安装落在正确 home（历史上曾落到错误目录）。

## 7. 登录 shell 兜底

侧边栏终端依赖登录 shell 环境；脚本在必要时补齐 PATH（含随包 node/pnpm 目录），保证终端可用。

## 8. 三端口一览

| 端口 | 用途 | 默认（SPK / FPK） |
|---|---|---|
| 反代端口 | 门户入口；token 认证 + 免密 cookie | 30800 / 3080 |
| DSH 原生端口 | DSH 自身监听 | 30801 / 3081 |
| 容器页端口 | 独立容器入口 | 30802 / 3082 |

端口权威在 `build/build-config.yaml`（`defaults` / `spk` / `fpk` 三段，**段名必须是映射** —— 读取方按 `sec.get('proxy_port')` 取值；写成标量会静默读不到端口段，守卫 `check-build-config.py` 会拦）。脚本与网页代码中禁止出现端口字面量，需要时调 `read_ports <system>`。
