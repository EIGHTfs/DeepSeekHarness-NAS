## 〇、先看这条：升级时提示「已卸载」

```
现象：手动升级到新版本，界面弹出「已卸载」
触发链：套件 preuninst → installer 的 preuninst() 以 DSH_UNINSTALLING=1 调 start-stop-status stop
        → start.sh 的 cmd_stop 检测到该变量，把「DSH 未运行」改说成「已卸载」
根因：群晖升级流程会调用 preuninst（旧版本被卸载），但 preuninst 未区分「升级」与「真卸载」
影响：升级场景措辞与事实不符，观感像装失败/被卸载
```

相关代码位置（仅供参考）：

```
- 提示输出：build/start.sh.example → cmd_stop 的「未运行」分支
- 置标记处：build/SPK/pack-spk.sh 的 preuninst()；已安装包 scripts/installer 同款一行
```

## 六、边界

- 只登记 `echo`/`printf` 直接输出的、给人读的文本；函数返回值与机器协议单列。
- 内嵌 JS 修复代码的 `console.log` 属日志，不在范围；写日志文件的行也不在范围。
- 安装向导文案取自 build/SPK/pack-spk.sh 的 JSON 生成段；FPK 侧若另有独立文案为另一套。
