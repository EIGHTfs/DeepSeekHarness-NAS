# 套件源（把任意 GitHub Release 变成 DSM 套件源）

手动下载 spk 装的包，DSM 无法比较版本，套件中心永不提示更新。只有来自「套件来源（package source）」的包才会进更新页，也才谈得上自动更新。

提供这个能力的是一个**零耦合单文件脚本**：`scripts/pkg-source.py`。给它任意 GitHub 仓库，它把该仓库 Release 里匹配到的 `*.spk` 资产整理成 DSM 能读的索引并对外提供。

## 1. 零耦合的含义（三条硬约束）

| 约束 | 含义 |
|---|---|
| 不依赖任何项目 | 只 import python3 标准库，不读本仓或任何项目的文件、不 import 项目代码 —— 拷到任意目录、任意机器都能直接跑 |
| 不假设产物命名 | 资产怎么匹配、架构怎么归类、包名叫什么，全部由 `--asset-regex` / `--arch-map` 参数决定，脚本里没有写死任何仓库的名字 |
| 不参与打包与下载 | 与 SPK/FPK 打包流程无关；spk 由**套件中心自己下载**，本工具只产出索引 JSON，默认一个字节都不下载 |

## 2. 职责边界

| 谁 | 做什么 |
|---|---|
| 本脚本 | 调 GitHub API 取 Release 资产列表（名字/大小/直链），生成并托管 `index-<arch>.json` |
| DSM 套件中心 | 按索引里的 `link` 自己下载 spk、安装、判断更新 |

因此索引里**不带 md5**：DSM 只按 `link` 下载，不做包体校验。要更强完整性约束，应在发布侧提供摘要（例如 Release 说明里的 sha256），而不是让本工具去下 190 MB 的包。

## 3. 三步用起来

```bash
# ① 起服务（换仓库只改 --repo，脚本不用动）
python3 scripts/pkg-source.py --repo owner/repo --port 8899

# ② 命名不同的仓库，用正则适配（必须含 package / arch / version 三个命名组）
python3 scripts/pkg-source.py --repo owner/repo \
    --asset-regex '(?P<package>[^_/]+)_(?P<arch>[A-Za-z0-9_]+)-(?P<version>[0-9][\w.\-]*)\.spk$'

# ③ DSM 套件中心 → 设置 → 套件来源 → 新增，按机型填：
#    x86_64：http://<运行脚本的机器IP>:8899/index-x86_64.json
#    armv8 ：http://<运行脚本的机器IP>:8899/index-armv8.json
```

默认正则匹配 `<包名>_<架构>-<版本>.spk`；架构别名默认 `aarch64=armv8`、`amd64=x86_64`，可用 `--arch-map` 覆盖。

## 4. 常用命令

```bash
python3 scripts/pkg-source.py --repo owner/repo --check          # 只生成并打印，不起服务
python3 scripts/pkg-source.py --repo owner/repo --once           # 生成一次即退出（cron）
python3 scripts/pkg-source.py --repo owner/repo --tag v1.2.3     # 固定某个 Release
python3 scripts/pkg-source.py --repo owner/repo --arches x86_64  # 只出某个架构
python3 scripts/pkg-source.py --from-spk-dir ./dist \
        --base-url https://example.com/dl --check                # 完全离线，用本地 spk
python3 scripts/pkg-source.py --out-dir /var/lib/pkg-source …    # 指定索引落盘目录
```

环境变量 `GH_TOKEN`（或 `GITHUB_TOKEN`）建议设置：取资产列表要调 GitHub API，匿名限流很低。

## 5. 独立部署（验证零耦合的方式）

```bash
cp scripts/pkg-source.py /anywhere/ && cd /anywhere
python3 pkg-source.py --repo owner/repo --check     # 不读任何项目文件也能出索引
```

脚本自身没有仓库路径概念：索引默认落在**当前目录**下的 `.pkg-source/`，不带任何项目内路径。

## 6. 索引格式

```json
{"packages": [{"package": "…", "version": "…", "link": "https://…/x.spk", "size": 123,
               "startable": "yes"}]}
```

| 字段 | 来源 | 说明 |
|---|---|---|
| `package` / `arch` / `version` | 资产名按 `--asset-regex` 解析 | 版本取自资产名，不读包内 INFO |
| `link` | Release 资产直链 | 套件中心据此下载 |
| `size` | GitHub API | 套件中心用于估算与显示 |

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 版本取资产名 | 若资产名里的版本与包内 `INFO` 的版本不一致，套件中心可能反复提示「有更新」；这类仓库应让发布产物名与 INFO 版本一致 |
| 无 md5 | 索引不带校验值，套件中心不做包体校验 |
| 只处理 `*.spk` | 其它扩展名需要改 `--asset-regex` |
| 需局域网可达 | DSM 与运行脚本的机器要在同一可达网段 |
| 未签名包 | 套件中心安装时提示「未知发行者」，属预期 |

## 8. 排错

| 现象 | 含义 | 处理 |
|---|---|---|
| 加源报「无法连接」 | 端口不通或 URL 写错 | `curl http://<IP>:<端口>/index-x86_64.json` 自测 |
| 索引返回 503 | 还没生成好 | 看服务日志的「刷新失败」原因 |
| 索引返回 404 | 路径或文件名不对 | 只服务 `index-<arch>.json` |
| 日志「跳过：…正则未取到 package/version」 | `--asset-regex` 与资产名不匹配 | 用 `--check` 看实际资产名后调整正则 |
