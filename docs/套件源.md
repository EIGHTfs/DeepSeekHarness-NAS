# 套件源（让套件中心发现新版本）

手动下载 spk 装的包，DSM 无法比较版本，套件中心永远不提示更新。只有来自「套件来源（package source）」的包才会出现在更新页，也才谈得上按 DSM 的自动更新设置升级。本文说明我们怎么提供这个源。

## 1. 索引格式

DSM 读的是一份 JSON，字段名取自 SynoCommunity 的现网响应（实测样本，不是推断）：

```json
{
  "packages": [
    {
      "package": "DeepSeekHarness-NAS",
      "dname": "DeepSeekRuntime NAS",
      "version": "0.2.2",
      "desc": "…",
      "link": "https://…/DeepSeekHarness-NAS_x86_64-0.2.2.spk",
      "md5": "0cdd6a4b…",
      "size": 173455360,
      "distributor": "DeepSeekHarness-NAS",
      "distributor_url": "https://github.com/EIGHTfs/DeepSeekHarness-NAS",
      "maintainer": "EIGHTfs",
      "changelog": "…",
      "startable": "yes"
    }
  ]
}
```

三条硬约束：

| 约束 | 原因 |
|---|---|
| `version` 必须与 spk 内 `INFO` 的 `version` **完全一致** | 不一致时 DSM 会认为索引与包对不上 |
| `md5` 与 `size` 必须是该 spk 真实值 | DSM 装包时校验，错了直接失败 |
| 索引按架构分文件 | DSM 是在服务端按请求里的 `?arch=&build=` 过滤的，静态托管做不到过滤，所以拆成 `index-x86_64.json` / `index-armv8.json`，用户按自己 NAS 架构添加 |

## 2. 生成

```bash
python3 scripts/gen-pkg-source.py \
  --spk build/staging/DeepSeekHarness-NAS_x86_64-<版本>.spk \
  --spk build/staging/DeepSeekHarness-NAS_armv8-<版本>.spk \
  --base-url https://github.com/EIGHTfs/DeepSeekHarness-NAS/releases/download/dsh-v<版本> \
  --out-dir pkg-source

python3 scripts/gen-pkg-source.py --spk <某个spk> --dry-run     # 只打印条目，不写文件
```

版本、大小、changelog 都从 spk 内的 `INFO` 现读，md5 现算，所以不会出现「索引写着 A、包里是 B」。

## 3. 托管

索引是静态文件，任何能被 DSM 访问到的 http(s) 地址都行：

| 方式 | 地址形态 |
|---|---|
| 仓库原始文件 | `https://raw.githubusercontent.com/<owner>/<repo>/main/pkg-source/index-x86_64.json` |
| 自建反代静态目录 | `http://<NAS-IP>:<端口>/pkg-source/index-x86_64.json` |
| 任意静态站点 | 把 `pkg-source/` 整个目录上传即可 |

`pkg-source/` 不入库（每次发版现场生成，避免库里躺着旧版本索引）。

## 4. 在 DSM 添加

```
套件中心 → 设置 → 套件来源 → 新增
  名称：随意（如 DeepSeekRuntime）
  位置：填对应架构的 index 文件 URL
保存后回套件中心，可见该包；之后的版本变化按 DSM 的自动更新设置处理
```

## 5. 已知局限

| 局限 | 说明 |
|---|---|
| 同一 patch 的多个预发布彼此不可区分 | 我们 `INFO` 版本取官方前三位（`0.2.3-alpha.1` 与 `alpha.2` 都是 `0.2.3`），DSM 认为版本相同 → 不会提示「alpha.1 可升到 alpha.2」。跨 patch（`0.2.2` → `0.2.3`）正常提示 |
| 架构要分开加 | 见第 1 节；加错架构的索引会看到不适用的包 |
| 包未签名 | DSM 安装时会有「未知发行者」提示，属预期 |
| 本索引是浏览型定位 | 目的是「让套件中心发现并安装我们当前的包」，不承诺同 patch 内的升级判定；要装历史版本仍从 Release 页手动下载 |

## 6. 待验证

真机在套件中心添加本索引后，需要确认三件事（尚未实测）：

1. 添加源后能否列出我们的包（`dname` / 图标 / 描述显示是否正常）；
2. 从源安装是否通过 md5 校验（`synopkg install_from_server` 路径）；
3. 已有旧版本时，更新页是否按版本号给出可更新提示。
