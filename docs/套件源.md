# 套件源（把任意 GitHub Release 变成 DSM 套件源）

手动下载 spk 装的包，DSM 无法比较版本，套件中心永不提示更新。只有来自「套件来源（package source）」的包才会进更新页，也才谈得上自动更新。

提供这个能力的是一个**零耦合单文件脚本**：`scripts/pkg-source.py`。给它任意 GitHub 仓库，它把该仓库 Release 里的 `*.spk` 资产整理成 DSM 能读的索引并对外提供。

## 1. 零耦合的含义（三条硬约束）

| 约束 | 含义 |
|---|---|
| 不依赖任何项目 | 只 import python3 标准库，不读本仓或任何项目的文件、不 import 项目代码 —— 拷到任意目录、任意机器都能直接跑 |
| 不假设产物命名 | 资产怎么匹配、架构怎么归类全部由 `--asset-regex` / `--arch-map` 参数决定；包名、版本、架构以包内 `INFO` 为准，不靠文件名猜 |
| 不下载整包 | 与 SPK/FPK 打包流程无关；spk 由**套件中心自己下载**。本工具只读每个资产的前 64KB 拿 `INFO`（实测 `INFO` 是 tar 的第一个成员），不落盘、不下 170MB 整包 |

## 2. 职责边界

| 谁 | 做什么 |
|---|---|
| 本脚本 | 调 GitHub API 取 Release 资产列表（名字/大小/直链），用 HTTP Range 读包头解析 `INFO`，生成并托管 `index-<arch>.json` |
| DSM 套件中心 | 按索引里的 `link` 自己下载 spk、安装、判断更新 |

因此目录里的 `md5` 字段**默认留空**：GitHub API 只提供 sha256 摘要，没有 md5；要拿 md5 得把整个包下下来算。但该键必须存在（缺键会让部分 DSM 版本跳过该条），需要用校验值时用 `--md5-file` 传入现成摘要。

## 3. 三步用起来

```bash
# ① 起服务（换仓库只改 --repo，脚本不用动）
python3 scripts/pkg-source.py --repo owner/repo --port 8899

# ② 需要多版本可比对时，聚合最近几个 Release（同包同架构自动留最高版本）
python3 scripts/pkg-source.py --repo owner/repo --releases 5 --port 8899

# ③ DSM 套件中心 → 设置 → 套件来源 → 新增，只填一个地址（不分机型）：
#    http://<运行脚本的机器IP>:8899/api/package
#    兼容路径 /nas、/nas/package、/index-<arch>.json 也可用，但不是首选
```

默认正则匹配 `<包名>_<架构>-<版本>.spk`；命名不符的（如 `<包名>_<架构>_<版本>-<构建>.spk`）会自动退到「用 `INFO` 兜底」，只在日志里留一行提示，不会静默丢包。架构别名默认 `aarch64=armv8,amd64=x86_64,x64=x86_64,arm64=armv8`，可用 `--arch-map` 覆盖。

## 4. 常用命令

```bash
python3 scripts/pkg-source.py --repo owner/repo --check           # 只生成并打印，不起服务
python3 scripts/pkg-source.py --repo owner/repo --once            # 生成一次即退出（cron）
python3 scripts/pkg-source.py --repo owner/repo --tag v1.2.3      # 固定某个 Release
python3 scripts/pkg-source.py --repo owner/repo --arches x86_64   # 只出某个架构
python3 scripts/pkg-source.py --repo owner/repo --verbose         # 显示展示名与套件版本差异
python3 scripts/pkg-source.py --force-silent-upgrade              # INFO 未声明时补 silent_upgrade
python3 scripts/pkg-source.py --auto-upgrade-from 0.2.0           # 指定允许自动升级的最低版本
python3 scripts/pkg-source.py --mirror https://ghfast.top/        # 读包头的镜像候选（直连自动兜底）
python3 scripts/pkg-source.py --link-mirror https://ghfast.top/   # 索引里下载地址的镜像前缀
python3 scripts/pkg-source.py --from-spk-dir ./dist \
        --base-url https://example.com/dl --check                 # 完全离线，用本地 spk
python3 scripts/pkg-source.py --out-dir /var/lib/pkg-source …     # 指定索引落盘目录
python3 scripts/pkg-source.py --arch-expand 'x86_64=x86_64,kvmx64'   # 覆盖架构代码族
python3 scripts/pkg-source.py --icon-base ''                        # 不输出缩略图
python3 scripts/pkg-source.py --md5-file ./md5.txt                  # 提供现成的 md5 清单
```

环境变量 `GH_TOKEN`（或 `GITHUB_TOKEN`）建议设置：取资产列表要调 GitHub API，匿名限流很低。

`--link-mirror` 的意义：本网络下 DSM 直连 GitHub Release 资产会失败（走 `objects.githubusercontent.com` 被拦），所以索引里的下载地址默认套一层镜像前缀，让套件中心能真正拉到包。传空串表示用原始直链。

## 5. 独立部署（验证零耦合的方式）

```bash
cp scripts/pkg-source.py /anywhere/ && cd /anywhere
python3 pkg-source.py --repo owner/repo --check     # 不读任何项目文件也能出索引
```

脚本自身没有仓库路径概念：索引默认落在**当前目录**下的 `.pkg-source/`，不带任何项目内路径。

## 6. 目录格式（`/api/package`）

套件中心认的是**单文件、所有架构混在一起、每条自带 `arch` 数组**的结构；按架构分文件的老式 `index-<arch>.json` 它不认，本工具已不再生成。

**关键：服务端必须按请求里的 `arch` 过滤后再返回。** DSM 会带 `arch=<本机代码>` 来问目录（本机 `kvmx64`、SA6400 是 `epyc7002`），而同一个包可能有多个架构条目（x86_64 与 armv8 各一个 spk）。若两条都返回，它取到不匹配本机的那条就把整包丢掉 —— 表现正是「源里明明有包、套件中心一个都不显示」。`spkrepo` 也是先按 arch 过滤，本工具与之对齐；`package_update_channel=stable` 时还会滤掉 `beta: true` 的包。

```json
{"packages": [{
  "package": "DeepSeekHarness-NAS", "version": "0.2.3-1002", "dname": "DeepSeekRuntime NAS",
  "arch": ["x64", "x86", "x86_64", "kvmx64", "epyc7002", "…"],
  "link": "https://…/x.spk", "size": 179507200, "md5": "", "signature": "",
  "os_min_ver": "7.0-40851", "silent_upgrade": "yes", "silent_install": "no",
  "qinst": true, "qupgrade": true, "start": true, "beta": true, "support_center": true,
  "thumbnail": [{"url": "http://<IP>:8899/icon/<包名>-72.png"}]
}]}
```

| 字段 | 形态 | 说明 |
|---|---|---|
| `package` / `version` / `dname` / `desc` | 字符串 | 取自包内 `INFO`（`package` / `version` / `displayname` / `description`）。**包名大小写必须与 `INFO` 一致**，否则 DSM 当成另一个套件 |
| `arch` | **数组** | 列该包兼容的全部架构代码。DSM 拿**本机代码**（本机 kvmx64、SA6400 是 epyc7002）去匹配，只写 `x86_64` 会在这些机型上不显示 |
| `link` / `size` | 字符串 / 整数 | Release 资产直链（可套 `--link-mirror`）与字节数 |
| `silent_install` / `silent_uninstall` / `silent_upgrade` | **布尔** | 与现役实现 `sspks-imnks` 一致。缺省按 `INFO` 取值，`--force-silent-upgrade` 可补成真 |
| `qinst` / `qstart` / `qupgrade` / `start` / `thirdparty` | 布尔 | `start` 恒 `true`（原生行为，不跟 `qstart` 走） |
| `price` / `download_count` / `recent_download_count` | **数字** | 原生给固定展示值，DSM 不校验 |
| `category` / `subcategory` / `type` | **数字** | 原生恒 `0`；写成字符串会让详情页类别异常（`--category-code` 可改） |
| `os_min_ver` | 字符串 | 低于该 DSM 版本不显示 |
| `md5` / `signature` | 字符串 | 键必须存在（缺失会让部分 DSM 版本跳过该条）；md5 拿不到时留空 |
| `thumbnail` / `snapshot` | 数组 `[{"url": …}]` | 默认由本服务托管包内图标（`/icon/<包名>-72.png`、`-256.png`），可用 `--icon-url` 改用外部静态图 |
| `changelog` / `support_url` / `url` | 字符串 | 详情页的「新版新增功能」「URL」两行读它们，缺了就显示成未替换的占位符 |
| `beta` | **不对外输出** | 仅在服务端按 `package_update_channel` 过滤时使用，返回给 DSM 前删除（与原生实现一致） |

**多语言**：条目里不直接给死 `dname`/`desc`，若 `INFO` 带 `displayname_chs` / `description_chs` 这类字段，会按请求的 `language` 参数覆盖，与 `sspks-imnks` 支持 21 种语言的方式相同。

同包同架构只保留**最高版本**一条：套件中心正是靠这条判断「有新版本可升级」。

## 7. 版本号规则（为什么以 INFO 为准）

群晖规定 `INFO` 的 `version` 每段只允许数字，本项目把预发布阶段编码进 build 段（`alpha` 基数 1000 / `beta` 2000 / `rc` 3000 / 正式 9000），详见 `docs/打包规范.md` 3.1 与 `build/tools/spk-version.py`。

因此同一个包会出现两种「版本」：

- 资产名里的 `0.2.3-alpha.2` —— 给人看的展示名；
- `INFO` 里的 `0.2.3-1002` —— 给 DSM 排序与比较用的真实版本。

套件中心记录「已装版本」用的是 `INFO` 的值，所以索引**默认也取 `INFO`**（`--version-source info`），两者同源才能正确判断升级。这也是同一 patch 的多个预发布能在 DSM 里正确排序（`alpha.1 < alpha.2 < rc.1 < 正式`）的前提。

两者不同是设计意图而非缺陷，故默认不打印告警；要看逐条对照加 `--verbose`。只有一类情况需要人工介入：老产物在打包时还没实现上述映射（`INFO` 写的是 `0.2.2`、资产名却是 `0.2.2-rc.5`），此时 rc 之间的升级识别不出来，应重新打包而不是改索引。

## 8. 已知限制

| 限制 | 说明 |
|---|---|
| md5 默认空 | GitHub 只给 sha256；要填 md5 需用 `--md5-file` 提供现成摘要，否则该字段为空串（套件中心不做包体校验） |
| 只处理 `*.spk` | fpk 与其它扩展名会被跳过并在日志里列出 |
| 需局域网可达 | DSM 与运行脚本的机器要在同一可达网段 |
| 未签名包 | 套件中心安装时提示「未知发行者」，属预期 |
| 只读包头 | `INFO` 若不在 tar 头部（极少见）会退到读 1MB 仍失败，此时该包被跳过并在日志说明原因 |
| 匿名限流 | 不设 `GH_TOKEN` 时 GitHub API 每小时 60 次，`--releases` 取多页时容易触顶 |

## 9. 排错

| 现象 | 含义 | 处理 |
|---|---|---|
| 加源报「无法连接」 | 端口不通或 URL 写错 | `curl http://<IP>:<端口>/index-x86_64.json` 自测 |
| 索引返回 503 | 还没生成好 | 看服务日志的「刷新失败」原因 |
| 索引返回 404 | 路径或文件名不对 | 只服务 `index-<arch>.json` |
| 日志「跳过：资产名不匹配」 | 不是 `*.spk`（如 fpk）或命名无法兜底 | 属预期；要收进来就调 `--asset-regex` |
| 日志「读取包头失败」 | 镜像与直连都不可达 | 换 `--mirror`，或先 `curl -r 0-1023 <资产直链>` 自测 |
| 套件中心能列出但下载失败 | `link` 指向的地址本网络不可达 | 设 `--link-mirror`，或把 spk 放本地后用 `--from-spk-dir` |
| 装了新版但套件中心还说有更新 | 索引版本与 `INFO` 不同源，或 `INFO` 版本没随发版递增 | 确认用默认 `--version-source info`；重新打包使 `INFO` 版本递增 |
