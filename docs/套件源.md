# 套件源（把任意 GitHub Release 变成 DSM 套件源）

手动下载 spk 装的包，DSM 无法比较版本，套件中心永不提示更新。只有来自「套件来源（package source）」的包才会进更新页，也才谈得上自动更新。

做法是一个**通用独立脚本** `scripts/pkg-source.py`：给它任意 GitHub 仓库，它把该仓库 Release 里的 `*.spk` 资产整理成群晖能读的索引并对外提供。它与被服务的项目**没有任何耦合**（不需要对方产出索引、不需要改对方 CI），也不与打包流程耦合。

## 1. 职责边界（关键）

| 谁 | 做什么 |
|---|---|
| 本脚本 | 只生成并托管**索引 JSON**：从 Release API 取资产名/大小/下载地址，按架构分文件提供 |
| DSM 套件中心 | **自己去下载 spk**（`link` 就是 Release 资产直链），校验并安装 |

所以脚本**默认不下载 spk**：190 MB 的包下载是套件中心的事。需要更强的完整性信息时才显式开开关：

| 开关 | 作用 | 代价 |
|---|---|---|
| `--with-md5` | 下载 spk 算 md5，写进索引（DSM 会校验） | 每个包下一次 |
| `--deep` | 下载 spk 读 INFO，取准确 `package`/`version`/`changelog` | 每个包下一次 |
| 默认（都不开） | 版本取资产名里的 `<版本>` 段，size 取 API 值，索引不带 md5 | 无下载；DSM 不做校验 |

默认模式下版本号来自资产名，若你的发布产物名与 spk 内 INFO 版本不一致，装完可能出现「一直提示有更新」——那种情况用 `--deep`。

## 2. 两步用起来

```bash
# ① 起服务（换仓库只改 --repo，脚本不用动）
python3 scripts/pkg-source.py --repo EIGHTfs/DeepSeekHarness-NAS --port 8899

# ② DSM 套件中心 → 设置 → 套件来源 → 新增，按机型填：
#    x86_64：http://<运行本脚本的机器IP>:8899/index-x86_64.json
#    armv8 ：http://<运行本脚本的机器IP>:8899/index-armv8.json
```

启动日志会打印这两条地址。之后套件中心会发现本包；有新版本时显示可更新，用户可在套件中心勾自动更新。

## 3. 常用命令

```bash
python3 scripts/pkg-source.py --repo <owner/repo> --check      # 只生成并打印，不起服务
python3 scripts/pkg-source.py --repo <owner/repo> --once       # 生成一次即退出（cron）
python3 scripts/pkg-source.py --repo <owner/repo> --tag v1.2.3 # 固定某个 Release
python3 scripts/pkg-source.py --repo <owner/repo> --arches x86_64   # 只出某个架构的索引
python3 scripts/pkg-source.py --from-spk-dir ./staging --base-url https://…   # 离线：用本地 spk
```

环境变量 `GH_TOKEN`（或 `GITHUB_TOKEN`）建议设置：GitHub API 匿名限流很低，取资产列表要调 API。

## 4. 索引格式与三条硬约束

```json
{"packages": [{"package": "...", "version": "...", "link": "https://…/x.spk", "size": 123, "md5": "…"}]}
```

| 约束 | 原因 |
|---|---|
| `link` 必须是套件中心能直接下载到的绝对地址 | DSM 自己下，脚本不中转 |
| `size` 取 Release 资产声明值 | 套件中心会据此估算与校验 |
| 按架构分文件 | DSM 在服务端按 `?arch=&build=` 过滤，静态托管做不到 |

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 只识别文件名含 `_x86_64-` / `_armv8-` 的 spk | 这是本项目的产物命名约定；别的项目命名不同需要调整 `ARCH_IN_NAME` |
| 未签名包 | 套件中心安装时提示「未知发行者」，属预期 |
| 需局域网可达 | DSM 与运行脚本的机器要在同一可达网段 |
| 同一 patch 的多个预发布区分不了 | 取决于发布方 INFO 版本是否递增（见 `打包规范.md` 的版本号映射） |

## 6. 排错

| 现象 | 含义 | 处理 |
|---|---|---|
| 加源报「无法连接」 | 端口不通/URL 错 | `curl http://<IP>:<端口>/index-x86_64.json` 自测 |
| 索引返回 503 | 还没生成好 | 看服务日志的「刷新失败」原因 |
| 索引返回 404 | 路径/文件名不对 | 只能访问 `index-<arch>.json` |
| 日志「跳过：… 缺 version」 | 发布方 INFO 异常 | 找发布方确认 spk 的 INFO |
