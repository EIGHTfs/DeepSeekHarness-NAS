# 局域网 SPK 套件源（套件中心自动更新）

手动下载 spk 装的包，DSM 无法比较版本，套件中心永不提示更新。只有来自「套件来源（package source）」的包才会进更新页，也才谈得上自动更新。

本目录提供的做法是**一个独立进程**：`scripts/pkg-source-server.py` 自己起 HTTP 端口、自己去 Release 取数据、自己定期刷新。它与套件本体、启动脚本、反代**没有任何耦合** —— 删掉套件也不影响它，反过来停掉它也不影响 DSH 运行。

## 1. 两步就能用

```bash
# ① 起本地源（缺省 8899 端口，每 30 分钟自动刷新）
python3 scripts/pkg-source-server.py --port 8899

# ② DSM 套件中心 → 设置 → 套件来源 → 新增，按机型填一条：
#    x86_64：http://<本机局域网IP>:8899/index-x86_64.json
#    armv8 ：http://<本机局域网IP>:8899/index-armv8.json
```

启动日志会直接打印上面两条地址。加源后套件中心能看到本包；之后有新版本会显示「可更新」，用户可在套件中心里勾自动更新，由 DSM 自己执行。

## 2. 数据从哪来

| 模式 | 触发条件 | 行为 |
|---|---|---|
| Release 索引资产（推荐） | Release 里有 `index-<arch>.json` | 只下载几 KB 的 JSON，无需碰 spk |
| 回退 | Release 里没有索引资产 | 下载 spk 资产并流式计算 md5（每个约 190 MB，仅版本变化时发生） |
| 离线 | 传 `--from-spk-dir` | 直接用本地 spk 目录生成索引，不访问网络 |

索引资产由发布流水线在打包后生成（`scripts/gen-pkg-source.py`，md5/size 取自本次真实产物），因此局域网侧永远只拉小文件。

## 3. 常用命令

```bash
python3 scripts/pkg-source-server.py --check                     # 只生成并打印，不起服务
python3 scripts/pkg-source-server.py --once                      # 生成一次就退出（给 cron / 计划任务）
python3 scripts/pkg-source-server.py --tag dsh-v<版本>            # 固定某个 Release，不跟最新
python3 scripts/pkg-source-server.py --interval 600              # 刷新间隔改成 10 分钟
python3 scripts/pkg-source-server.py --from-spk-dir build/staging \
        --base-url https://example.com/releases                   # 离线模式（例如还没发布）
```

环境变量 `GH_TOKEN`（或 `GITHUB_TOKEN`）建议设置：GitHub API 匿名限流很低，回退模式又必须调 API 取资产列表。

## 4. 索引格式与三条硬约束

```json
{"packages": [{"package": "...", "dname": "...", "version": "0.2.3-1002",
               "link": "https://…/xxx.spk", "md5": "…", "size": 173455360, "changelog": "…"}]}
```

| 约束 | 原因 |
|---|---|
| `version` 必须与 spk 内 `INFO` 的 `version` 完全一致 | 不一致时 DSM 认为索引与包对不上 |
| `md5` 与 `size` 必须是该 spk 的真实值 | 套件中心装包时校验，错了直接失败 |
| 索引按架构分文件 | DSM 在服务端按请求里的 `?arch=&build=` 过滤，静态托管做不到 |

## 5. 已知限制

| 限制 | 说明 |
|---|---|
| 同一 patch 的多个预发布区分不了 | `INFO` 的版本取官方前三位时，同 patch 的预发布版本号相同，DSM 认为「没有更新」。想区分就得把预发布阶段编码进 build 段（见 `打包规范.md` 的版本号映射） |
| 包未签名 | 套件中心安装时会提示「未知发行者」，属预期 |
| 只服务白名单文件名 | 服务端只认 `index-x86_64.json` / `index-armv8.json`，其余路径 404 |
| 需局域网可达 | DSM 与运行本服务的主机要在同一可达网段；跨网段需自行打通 |

## 6. 排错

| 现象 | 含义 | 处理 |
|---|---|---|
| 套件中心加源报「无法连接」 | 端口不通或 URL 写错 | `curl http://<IP>:<端口>/index-x86_64.json` 自测 |
| 拉索引返回 503 | 索引还没生成好 | 看服务日志的「刷新失败」原因（网络/令牌/资产缺失） |
| 拉索引返回 404 | 路径或文件名不对 | 只能访问那两个白名单文件名 |
| 日志提示「缺架构索引」 | 只有一个架构的产物 | 该架构机型加源后看不到包，等对应架构发布后再刷新 |
| 套件中心有包但永远「无更新」 | 版本号没变（见限制第 1 条） | 确认本次发布确实抬了版本 |
