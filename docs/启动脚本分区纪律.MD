# 20261118 启动脚本分区纪律（解析区函数化）

> 设计角度的方案文档，供执行者使用。全部完成并验证后，再改写为面向使用者的功能介绍。

## 门禁表

| 项 | 内容 |
|---|---|
| 任务 | 在保持单文件前提下，给 `build/pkgsrc/start.sh.example` 建立可识别、可 source 复用、可自检的分区纪律；把解析区顶层代码包进 `resolve_environment()` |
| 验收标准 | ① `bash -n` 通过；② `source start.sh` 不启动服务、不执行 main；③ `start.sh self-check` 输出固定格式摘要、异常非 0 退出；④ `start/stop/restart/status/check/fix-*` 行为逐字不变；⑤ 解析结果（PKG_VERSION / 包名 / DSH_HOME / NODE_BIN）与改造前一致 |
| 不做什么 | 不拆文件、不改业务逻辑、不改占位符注入、不动已装机脚本、不做自更新 |

## 一、目标

- 问题：今晚两个 bug（写穿软链真身、包名用 `basename(DSH_DIR)` 得字面量 target）都在启动脚本解析区，且都不报错。根因不是"文件太大"，是"解析混在顶层、无边界、无自检"。
- 期望效果：解析逻辑可被单独 source 验证；明显异常当场报错而非静默降级；单文件约束不变。
- 成功标准：门禁表五条全部可脚本化断言。

## 二、风险与边界

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 包进函数改变变量作用域 | 中 | heredoc / trap / 子进程取不到变量 | 解析区内变量保持全局赋值（不加 `local`）；逐段对比行为 |
| source 保护改变执行时机 | 低 | 直接执行时 main 不跑 | 仅 main 分发处加 `[ "${BASH_SOURCE[0]}" = "$0" ]` 守卫 |
| 解析区含 `exit` / `cd` 等副作用 | 中 | 函数化后 `exit` 会退出整个 shell（含 source 场景） | 通读识别所有副作用，逐个决定保留或改成 return |
| 新增命令撞名 | 低 | 与现有 `check` 混淆 | 用独立名 `self-check`，只读、不改状态 |
| 占位符被误替换 | 低 | 生成脚本异常 | 不碰 `__XXX__` 占位区域 |

边界条件：① 被 source 时只定义函数、不执行动作；② 直接执行无参数时行为与改造前完全一致；③ self-check 在缺依赖/异常时明确报错而非静默降级；④ 并发多实例时解析只读、无写竞争。

## 三、复用调研

| 检查项 | 结果 | 说明 |
|---|---|---|
| 已有同类 skill | 有 | `skills/execution-执行/syno-spk-package-guide.md` 第八节：单文件是刻意目标，推荐 A′ 文件内分区 + 内置自检；本次正是层次 2（解析区函数化） |
| 已有同类机制 | 有 | 现有 `cmd_check()`（只读自检）—— self-check 复用其结论抽取，不重复造 |
| 官方做法 | 有 | bash 惯例 `[ "${BASH_SOURCE[0]}" = "$0" ]` 做 source 保护 |
| 现成库 | 无 | 单文件约束排除任何外部库 |

结论：分区 = 注释标记 + source 保护 + 解析函数 + 自检子命令，四件事都在同一文件内完成。

## 四、影响范围

- 涉及文件：`build/pkgsrc/start.sh.example`（唯一母版）。最终 `start.sh` 由 `pack-spk.sh` / `pack-fpk.sh` sed 注入占位符生成，自动继承改动。
- 调用方：套件生命周期（start/stop/status）、用户手工执行、CI 打包生成链。
- 会破坏什么：解析区变量若漏出作用域，可能导致 `DSH_HOME` / `PKG_VERSION` 为空 → 服务起不来。故全程保持全局赋值并做前后值比对。
- 影响维度：现有功能 中（main 与解析区改动，需逐条回归）、兼容性 中（生成链未变）、可维护性 高（收益）、性能/安全 低。
