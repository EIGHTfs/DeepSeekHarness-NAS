# 使用指南

面向使用者：装完之后怎么用。构建与发布见 `构建与发布指南.md`，包结构见 `打包规范.md`，出问题按 `故障排查指南.md` 走。

## 1. 获取安装包

| 方式 | 操作 |
|---|---|
| GitHub Release | 下载对应平台的产物：群晖 `DeepSeekHarness-NAS_x86_64-<版本>.spk`、飞牛 `DeepSeekHarness-NAS_x86-<版本>.fpk`（ARM 为 `_armv8-` / `_arm-`） |
| 网页安装工具 | 本机 `build/staging/` 与 `release/` 里的包直接被扫描到，无需手动下载 |
| 校验 | Release 正文含每个产物的 sha256，下载后 `sha256sum <文件>` 对照 |

基线版本随官方滚动，产物文件名与 Release tag 就是版本号。

## 2. 安装

### 群晖 DSM

1. 套件中心 → 套件设置 → 手动安装 → 选择 `.spk`。
2. 安装向导填端口：**留空即用打包默认**（30800 / 30801 / 30802）。三端口都可填，用于同机多实例用不同端口并存。
3. 安装完成后在 DSM 桌面点套件图标打开。

要求：DSM 7.0-40851 及以上，x86_64（包内自带 node，无需另装）。

### 飞牛 fnOS

1. 应用中心 → 手动安装 → 选择 `.fpk`（首次需开启手动安装：`appcenter-cli manual-install enable`）。
2. 选择安装卷后确认。要求 fnOS 1.1.0 及以上。

### 远程一键安装（可选）

网页安装工具已拆分为独立仓库，需要远程安装时按该仓库 README 操作：

- 仓库：https://github.com/EIGHTfs/nas-pkg-installer

本仓不再包含该工具的代码、配置模板与远程脚本。

## 3. 访问与端口

| 平台 | 反代端口（用户入口） | dsh 原生端口（仅本机回环） | 容器页端口 |
|---|---|---|---|
| 群晖 | 30800 | 30801 | 30802 |
| 飞牛 | 3080 | 3081 | 3082 |

对外一律走反代端口：

```
http://<NAS-IP>:30800      # 群晖
http://<NAS-IP>:3080       # 飞牛
```

`<NAS-IP>` 取 NAS 主网卡局域网地址（在 NAS 上执行 `hostname -I`，排除 `172.17.*` 等容器网桥段）。

反代端口的访问规则：

| 来源 | 结果 |
|---|---|
| 从 DSM/fnOS 桌面套件图标打开 | 入口 URL 自带当次 token → 认证后种 `dsh-auth` cookie，页面收敛为干净地址 |
| 认证过的浏览器直接访问 | 带 cookie 放行，局域网内免密 |
| 地址栏首次直接访问（从未从图标打开过） | 403「请从套件图标打开」 |
| 公网 IP 来源 | 403 中文提示页（先于一切认证逻辑） |

端口改法：改 `build/build-config.yaml` 的 `defaults` / `spk` / `fpk` 段后重新打包；或运行时用 `--proxy-port` / `--dsh-port` / `--container-port` 覆盖（写入数据目录的 `ports`，跨升级保留）。spk 用 30800 段、fpk 用 3080 段，可同机共存。

### 登录（OAuth）需要回环访问

浏览器登录只接受回环来源（`http://localhost:<端口>`、`http://127.0.0.1:<端口>`、`http://[::1]:<端口>`）。直接访问 `http://<NAS-IP>:<反代端口>` 点「登录」会失败：弹窗一闪而过（about:blank），界面提示「登录失败 / 操作未完成」。平台侧同样校验，改包内代码也无效。

用仓库自带脚本建本地转发（端口由脚本从目标机读取，无需手填）：

```bash
scripts/connect-local.sh <NAS-IP>                 # Linux / macOS
scripts/connect-local.bat                         # Windows：双击后按提示输入 NAS 地址
```

默认把远端反代端口转发到本机同号端口；本机端口被占用时换一个：

```bash
LOCAL_PORT=31800 scripts/connect-local.sh <NAS-IP>
```

隧道建好后在 `http://127.0.0.1:<端口>` 里完成登录，按 `Ctrl-C` 断开。不需要登录时改用 API Key：设置 → 账号 → 添加 API Key。

## 4. 日常操作

```bash
cd /var/packages/DeepSeekHarness-NAS/target           # 群晖（飞牛：/vol2/@appcenter/DeepSeekHarness-NAS）
./bin/start.sh status                                 # 0=运行中，3=未运行
./bin/start.sh restart                                # 重启（未启动时相当于 start）
./bin/start.sh stop                                   # 停止
./bin/start.sh fix-deps                               # 启动报缺包时补齐
./bin/start.sh gen-portal --token                     # 重新生成门户入口并写入当次 token
```

平台侧启停：

```bash
synopkg start DeepSeekHarness-NAS                     # 群晖（stop/restart/status 同名）
appcenter-cli start DeepSeekHarness-NAS               # 飞牛（stop/status/check 同名）
```

## 5. 配置模型

Web UI → 设置 → Models → 添加提供方。或直接编辑配置文件：

```
/var/packages/deepseek-harness-nas/target/var/data/.dsh/settings.yaml
/var/packages/deepseek-harness-nas/target/var/data/.dsh/.credentials.yaml
```

自定义 OpenAI 兼容端点的写法：

```yaml
providers:
  myprovider:
    id: myprovider
    name: My Provider
    type: openai-completions
    base_url: https://api.example.com/v1
    models:
      - id: my-model
        name: my-model
```

```yaml
API_KEYS:
  DEEPSEEK_API_KEY: "<你的 API 密钥>"
```

DeepSeek 官方端点为 `https://api.deepseek.com/v1`，Bearer Token 认证。

## 6. 命令行 `dsh` 与 `pnpm`

安装后 SSH 登录 NAS 直接可用，无需进套件目录：

```bash
dsh --version
dsh plugin --profile web list                 # 查看已装插件
dsh plugin --profile web add <包名>            # 安装插件
pnpm --version
```

`dsh` 与 `pnpm` 都是随包 wrapper，内部注入套件自己的 `DSH_HOME`，因此**插件装进去的位置和服务读取的位置是同一个**。若用户自行 `export DSH_HOME`，wrapper 尊重该值不覆盖。

装完或改完插件需要重启服务才会加载：群晖 `synopkg restart DeepSeekHarness-NAS`，飞牛 `appcenter-cli stop <app> && appcenter-cli start <app>`。

## 7. 数据目录与多版本

| 内容 | 位置 |
|---|---|
| 程序 | 群晖 `/var/packages/<app>/target`；飞牛 `/vol2/@appcenter/<app>`（`/var/apps/<app>/target` 是它的软链） |
| 数据（按版本隔离） | 群晖 `/var/packages/<app>/var/<版本>/`；飞牛 `/vol2/@appdata/<app>/<版本>/` |
| 端口记录 | `<数据目录>/<版本>/ports` |
| 反代日志 | `<数据目录父级>/dsh-proxy.log` |
| 平台临时目录 | 飞牛 `/vol2/@apptemp/<app>`；群晖 `/var/packages/<app>/tmp` |

数据目录按版本隔离，同机不同版本各有自己的一份配置、会话与凭据，互不共享。

## 8. 卸载 / 保留数据 / 回退旧版

卸载向导默认「仅卸载（保留文件）」，只有选「彻底删除数据」才清理数据目录。

```
回退旧版三步：
① 从对应 Release tag 下载旧版包
② 在 Web UI 卸载当前版本（保持默认「保留数据」）
③ 安装旧版包 → 启动（端口沿用数据目录里记录的，无需重填）
```

命令行卸载会被平台拒绝（提示从 Web UI 卸载）。卸载流程会先调用 `start.sh stop`，此时输出「已卸载」。

修复（repair）同样默认保留数据：只清程序残留，不碰 `@appdata` / `@apphome` / `@appshare`。要连数据一起删需显式选择：

```bash
scripts/clean-dsm-residue.sh DeepSeekHarness-NAS --delete-data # 残留清理并删数据
```

同一包名 = 同一套端口与同一个桌面图标，两个版本无法同时在线。需要双实例时用不同端口段各装一份，或另建带后缀的包名。

## 9. 资源限制

飞牛（fnOS）的 CPU 配额走 systemd `CPUQuota`：

```bash
scripts/set-dsh-cpu-quota.sh          # 写入 systemd CPUQuota 并重启应用中心服务
scripts/verify-dsh-cpu-quota.sh       # 校验配置与 cgroup 实际限制是否一致
```

生效值可直接读：`systemctl show trim_app_center.service --property=CPUQuota`，以及 `/sys/fs/cgroup/system.slice/trim_app_center.service/cpu.max`（形如 `300000 100000` = 300%）。

群晖（DSM）**不要照搬上面的做法**：群晖内核没有 CFS 带宽，`CPUQuota` 会「显示成功但不生效」，内存限制属性名也不是 `MemoryMax`。群晖侧一律改用 `taskset` 绑核 + `MemoryLimit`，并注意重启后的 cgroup 归属，完整做法与验证命令见 [群晖资源限制](群晖资源限制.md)。

## 10. 安全模式

DSH 启动失败时，Web UI 提供一键禁用所有用户插件的入口，用于排除插件导致的启动异常；排除后逐个恢复定位问题插件。
