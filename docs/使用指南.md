# 使用指南

装完之后怎么用。构建与发布见 `构建与发布指南.md`，包结构见 `打包规范.md`，出问题按 `故障排查指南.md` 走。

## 1. 获取安装包

| 方式 | 操作 |
|---|---|
| GitHub Release | 下载对应平台产物：群晖 `DeepSeekHarness-NAS_x86_64-<版本>.spk`、飞牛 `DeepSeekHarness-NAS_x86-<版本>.fpk`（ARM 为 `_armv8-` / `_arm-`） |
| 校验 | Release 正文含每个产物的 sha256，下载后 `sha256sum <文件>` 对照 |

产物文件名与 Release tag 就是版本号。

## 2. 安装

### 群晖 DSM

1. 套件中心 → 套件设置 → 手动安装 → 选择 `.spk`。
2. 安装向导填端口，**留空即用打包默认**（30800 / 30801 / 30802）。三端口都可填，用于同机多实例并存。
3. 装完在 DSM 桌面点套件图标打开。

要求：DSM 7.0-40851 及以上，x86_64（包内自带 node，无需另装）。

### 飞牛 fnOS

1. 应用中心 → 手动安装 → 选择 `.fpk`（首次需 `appcenter-cli manual-install enable`）。
2. 选择安装卷后确认。要求 fnOS 1.1.0 及以上。

远程安装/卸载由独立仓库的工具承担，本仓只负责打包与发布。

## 3. 访问与端口

| 平台 | 反代端口（用户入口） | dsh 原生端口（仅回环） | 容器页端口 |
|---|---|---|---|
| 群晖 | 30800 | 30801 | 30802 |
| 飞牛 | 3080 | 3081 | 3082 |

对外一律走反代端口：

```
http://<NAS-IP>:30800      # 群晖
http://<NAS-IP>:3080       # 飞牛
```

`<NAS-IP>` 取 NAS 主网卡地址（`hostname -I`，排除 `172.17.*` 等容器网桥段）。

反代端口的访问规则：

| 来源 | 结果 |
|---|---|
| 从 DSM/fnOS 桌面图标打开 | 入口 URL 自带当次 token，认证后种 `dsh-auth` cookie，页面收敛为干净地址 |
| 认证过的浏览器直接访问 | 带 cookie 放行，局域网免密 |
| 地址栏首次直接访问 | 403「请从套件图标打开」 |
| 公网 IP 来源 | 403 中文提示页（先于一切认证逻辑） |

改端口：改 `build/build-config.yaml` 的 `defaults` / `spk` / `fpk` 段后重新打包；或运行时用 `--proxy-port` / `--dsh-port` / `--container-port` 覆盖（写入数据目录的 `ports`，跨升级保留）。spk 用 30800 段、fpk 用 3080 段，可同机共存。

### 登录（OAuth）需要回环访问

浏览器登录只接受回环来源（`localhost` / `127.0.0.1` / `[::1]`）。直接访问 `http://<NAS-IP>:<反代端口>` 点登录会失败：弹窗一闪而过，界面提示「登录失败 / 操作未完成」。平台侧同样校验，改包内代码无效。

用仓库脚本建本地转发（端口由脚本从目标机读取）：

```bash
scripts/connect-local.sh <NAS-IP>                 # Linux / macOS
scripts/connect-local.bat                         # Windows：双击后按提示输入 NAS 地址
LOCAL_PORT=31800 scripts/connect-local.sh <NAS-IP> # 本机端口被占用时换端口
```

隧道建好后在 `http://127.0.0.1:<端口>` 完成登录，`Ctrl-C` 断开。不需要登录时改用 API Key：设置 → 账号 → 添加 API Key。

## 4. 日常操作

```bash
cd /var/packages/DeepSeekHarness-NAS/target           # 群晖（飞牛：/vol2/@appcenter/DeepSeekHarness-NAS）
./bin/start.sh status                                 # 0=运行中，3=未运行
./bin/start.sh restart                                # 重启（未启动时相当于 start）
./bin/start.sh stop                                   # 停止
./bin/start.sh fix-deps                               # 启动报缺包时补齐
./bin/start.sh gen-portal --token                     # 重新生成门户入口并写入当次 token
```

平台侧启停：

```bash
synopkg start DeepSeekHarness-NAS                     # 群晖（stop/restart/status 同名）
appcenter-cli start DeepSeekHarness-NAS               # 飞牛（stop/status/check 同名）
```

## 5. 命令行 `dsh` 与 `pnpm`

装完 SSH 登录 NAS 直接可用：

```bash
dsh --version
dsh plugin --profile web list                 # 查看已装插件
dsh plugin --profile web add <包名>            # 安装插件
pnpm --version
```

两者都是随包 wrapper，内部注入套件自己的 `DSH_HOME`，所以插件装进去的位置与服务读取的位置一致；用户自行 `export DSH_HOME` 时 wrapper 尊重该值不覆盖。

装完或改完插件需重启服务才加载：群晖 `synopkg restart DeepSeekHarness-NAS`，飞牛 `appcenter-cli stop <app> && appcenter-cli start <app>`。

## 6. 数据目录与多版本

| 内容 | 位置 |
|---|---|
| 程序 | 群晖 `/var/packages/<app>/target`；飞牛 `/vol2/@appcenter/<app>`（`/var/apps/<app>/target` 是其软链） |
| 数据（按版本隔离） | 群晖 `/var/packages/<app>/var/<版本>/`；飞牛 `/vol2/@appdata/<app>/<版本>/` |
| 端口记录 | `<数据目录>/<版本>/ports` |
| 反代日志 | `<数据目录父级>/dsh-proxy.log` |
| 平台临时目录 | 飞牛 `/vol2/@apptemp/<app>`；群晖 `/var/packages/<app>/tmp` |

同机不同版本各有自己的配置、会话与凭据，互不共享。

## 7. 卸载 / 保留数据 / 回退旧版

卸载向导默认「仅卸载（保留文件）」，只有选「彻底删除数据」才清理数据目录。

```
回退旧版三步：
① 从对应 Release tag 下载旧版包
② 在 Web UI 卸载当前版本（保持默认「保留数据」）
③ 安装旧版包 → 启动（端口沿用数据目录里记录的，无需重填）
```

命令行卸载会被平台拒绝（提示从 Web UI 卸载）。卸载流程会先调用 `start.sh stop`，此时输出「已卸载」。

修复（repair）同样默认保留数据：只清程序残留，不碰 `@appdata` / `@apphome` / `@appshare`。要连数据一起删需显式选择：

```bash
scripts/clean-dsm-residue.sh DeepSeekHarness-NAS --delete-data
```

同一包名 = 同一套端口与同一个桌面图标，两个版本无法同时在线。需要双实例时用不同端口段各装一份，或另建带后缀的包名。

### 7.1 把旧版本的数据迁到新版本

升级后新版本用新目录，旧版本数据留在原地。要把设置、凭据、插件配置与会话带过来，用仓库里的独立工具（不随包分发）：

```bash
./migrate-dsh-home.sh list                                    # 1) 看有哪些旧版本可迁（只读）
./migrate-dsh-home.sh migrate --from <旧版本> --dry-run        # 2) 演练，不写盘
./migrate-dsh-home.sh migrate --from <旧版本> --confirm        # 3) 真执行（默认连会话；只要配置加 --config-only）
./migrate-dsh-home.sh prune --version <旧版本> --confirm       # 4) 新版本确认正常后归档旧数据（改名不删除）
```

一次只能选一个源（多版本合并会互相覆盖）。工具处理三处易踩点：属主归正到套件用户与套件组、凭据文件强制 600（否则 credentials 插件拒启）、用 tar 管道复制以保留软链形态。目标已有数据时先整目录改名为 `.dsh.bak-<时间戳>`，回滚只需 `mv` 回来。

两条前提：

- 以套件用户身份运行（脚本会提示切换命令），否则复制出来的属主不对；
- 目标版本默认取「实际安装的版本」（读包内 `package.json` 的 `version`，不按目录名猜）；要写别的版本用 `--target <完整版本>`，工具会标明版本来源。

会话格式无需额外处理：DSH 自带 v0→v4 迁移链，读旧格式时自动转换，迁移工具只负责搬文件。

## 8. 资源限制

飞牛（fnOS）的 CPU 配额走 systemd `CPUQuota`：

```bash
scripts/set-dsh-cpu-quota.sh          # 写入 systemd CPUQuota 并重启应用中心服务
scripts/verify-dsh-cpu-quota.sh       # 校验配置与 cgroup 实际限制是否一致
```

生效值直接读：`systemctl show trim_app_center.service --property=CPUQuota`，以及 `/sys/fs/cgroup/system.slice/trim_app_center.service/cpu.max`（形如 `300000 100000` = 300%）。

群晖不要照搬：群晖内核没有 CFS 带宽，`CPUQuota` 显示成功但不生效，内存限制属性名也不是 `MemoryMax`。群晖侧用 `taskset` 绑核 + `MemoryLimit`，并注意重启后的 cgroup 归属，见 [群晖资源限制](群晖资源限制.md)。

## 9. 安全模式

DSH 启动失败时，Web UI 提供一键禁用所有用户插件的入口，用于排除插件导致的启动异常；排除后逐个恢复定位问题插件。
