# 打包规范

SPK / FPK 的包结构、生成物约定与出货不变量。构建流程与 CI 见 `构建与发布指南.md`。

## 1. 两种包的形态差异

| | SPK（群晖） | FPK（飞牛） |
|---|---|---|
| 载荷 | `package.tgz`，保留软链 | `app.tgz`，**必须删软链** |
| 原因 | DSM 安装对软链无意见 | fnOS 解压逐条目设 ACL，软链会让 `acl_get_file failed` |
| 缺一个包的后果 | 软链完整时往往仍能解析到，可能侥幸能跑 | 硬缺 → 插件直接 failed to import |
| 入口/按钮注册 | 由 `INFO` + `ui/config` 驱动，安装即注册 | 由**应用中心判定启动成功**驱动 |

凡在 FPK 上验证过的缺陷，SPK 也要回归一次；反之不成立。SPK 载荷里的悬空软链不影响安装可用（DSM 原样解软链、dev/可选包本就不需要、运行期还有 `start.sh` 自愈），所以结构比对工具对此只给提示，不作硬判据。

## 2. FPK 载荷后处理（三步缺一不可）

`app.tgz` 生成后：

1. 记录全部软链到外层 `links.tar`（只含软链条目，`tar --no-recursion -T`）；
2. 删除 `app.tgz` 内全部软链；
3. 所有条目 `uid/gid` 归 root，目录 755 / 文件 644（`tar --owner=0 --group=0 --numeric-owner`）。

安装期还原必须 `tar -xf links.tar -C <应用体>` 原样解回；**不要用文本清单逐行 `ln -s`**：数千条里会错数百条（含主包），导致插件 failed to import。

不要依赖 fnOS 解出外层自定义文件：`links.tar` 在应用目录和应用体里都可能取不到，真正兜底的是 `start.sh` 的启动期三层链接自愈。

打包脚本用 `tar --hard-dereference` 复制替代 `cp -a`，避免软链被带进载荷。

## 3. SPK 结构与权限

| 内容 | 要求 |
|---|---|
| 外层 tar | 条目不带 `./` 前缀 |
| 权限 | 目录 755、文件 644、脚本 755；非标准位（如 `0707`）被拒（`failed to revise file attributes`，313） |
| `INFO` 版本号 | 官方版本前三位（`<版本>-<预发布>` → `<版本>`），无 build 后缀，同版本覆盖安装 |
| FPK `manifest` 版本号 | 完整串（含预发布后缀） |
| `resource` 段 | 不能写 systemd-unit |
| 门户资源 | `ui/` + `spk-templates/ui-config.json` 打进 package.tgz，安装时建 `webman/3rdparty/<app>` 链接 |

## 4. 门户注册（DSM）

| 文件 | 字段 | 要求 |
|---|---|---|
| `INFO` | `dsmappname="SYNO.SDS.XXX.Application"` | 去连字符（`DeepSeekHarness-NAS` → `DeepSeekHarnessNAS`） |
| `ui/config` | `.url."SYNO.SDS.XXX.Application"` | 必须与 `INFO` 的 `dsmappname` **逐字一致** |
| `ui/config` | `protocol` + `port` | 由 DSM 自动拼 NAS 真实地址，**不写死 url/IP** |

`ui/config` 写法：

```json
{
    ".url": {
        "SYNO.SDS.XXX.Application": {
            "type": "url",
            "protocol": "http",
            "port": "30800",
            "icon": "images/icon_{0}.png",
            "title": "显示名",
            "allUsers": false
        }
    }
}
```

两处不一致 → 桌面图标点不开、套件中心无「打开」按钮。生成门户的模板用 `__APP_ID__`（去连字符）而非 `__APP_NAME__`（带连字符）。

FPK 侧门户 `<应用体>/ui/config` 的 `url` 必须是**固定 `/`**：写成 `/?token=…` 会让飞牛「打开」按钮点不开。带 token 的入口由运行期 `sync_portal_token()` 写入。

### 4.1 点击「打开」的完整链路

```
DSM 读 INFO 的 dsmuidir=ui + dsmappname
  → 找到 ui/config 里的同名条目，用 protocol + port 拼 http://<NAS-IP>:<反代端口>/
  → 请求落到反代（start.sh）
  → 反代判定「来自门户 + 无 dsh 会话」→ 302 到 ?token=<当次运行 token>
  → dsh 收到 token → 303 回干净 URL 并种下 dsh-auth cookie（地址栏 token 随即隐藏）
```

两条硬约束：

| 约束 | 后果 |
|---|---|
| token **不写进** `ui/config`（`url` 不带参数） | 写 `/?token=…` 会让「打开」按钮失效；免密由反代自动完成 |
| **不能用** `adminport` / `adminurl` / `adminprotocol` | 这三个让套件中心直接跳静态地址，绕开反代补 token 的逻辑；若指向 dsh 原生端口等于完全跳过鉴权 |

### 4.2 INFO 可选字段取舍

依据 `docs/官方文档/spk/synology_package__INFO_optional_fields.md`（群晖官方字段说明）：

| 字段 | 官方语义 | 本项目 |
|---|---|---|
| `helpurl` | 装好后套件详情页显示「帮助」网页超链接 | **启用**，值取 `build-config.yaml` 的 `helpurl`（本仓库地址） |
| `support_url` | 套件中心显示支持链接，便于用户求助 | **启用**，值取 `build-config.yaml` 的 `support_url` |
| `support_conf_folder` | DSM 5.2 及更早要使用 `conf/` 目录时须设 `yes`；**DSM 6.0 起已废弃** | 不设（目标系统 ≥ DSM 7） |
| `checkport` | 检查 `adminport` 与 DSM 已保留/监听端口冲突（排除 80/443/5000/5001）；**默认已是 yes** | 不设（不声明 `adminport`，默认即开） |
| `adminport` / `adminurl` / `adminprotocol` | 套件中心「打开」指向的静态地址与端口 | 不用（会绕开 4.1 的门户 token 鉴权） |
| `os_max_ver` | 封顶可安装的 DSM 版本 | 待评估（取值语义未核实，不贸然加） |

## 5. 安装向导（SPK）

`WIZARD_UIFILES/` 走群晖官方机制，安装/卸载时弹窗收集参数，值以 `wizard_*` 环境变量传给 `scripts/installer`：

| 向导 | 字段 | 行为 |
|---|---|---|
| 安装 | `wizard_proxy_port` / `wizard_dsh_port` / `wizard_container_port` | 可空 = 打包默认；`postinst` 写入 `<数据目录>/<版本>/ports`，`start-stop-status` 优先读它（跨升级保留）→ 同机多实例不同端口并存 |
| 卸载 | `wizard_keep_data` | 默认「仅卸载（保留文件）」；选「彻底删除」才清数据目录 |

中英双份：`install_uifile`(+`_chs`) / `uninstall_uifile`(+`_chs`)。

同名套件重装一律按全新安装处理（DSM 先清 `/var/packages/<pkg>` 再重建），版本号被新包覆盖；数据在 `@appdata` 的版本隔离目录，不受影响。要多版本同时安装需改版本化包名（当前不采用）。

安装期改端口只用 `sed` 精确匹配 `"port"` 一行，不重写整个 `ui/config`，以免冲掉运行期写入的 `url` 字段。

## 6. 生成物（`cmd/main`、`start-stop-status`）

两个平台的启停脚本都由打包脚本从 `build/start.sh.example` 母版生成（占位符 `__PROXY_PORT__` / `__DSH_PORT__` / `__CONTAINER_PORT__` / `__APP_ID__` 按平台替换）。生成物是引号 heredoc（`<<'EOF'`），有两条铁律：

1. **自包含**：生成物里调用的函数必须在生成物内有定义。实现放在 `scripts/lib/common.sh` 不等于生成物能用 —— 缺 `running_dsh` 定义会让真机 `cmd/main status` 报「未找到命令」，平台判定启动失败。
2. **端口用运行时值**：写 `${DSH_PORT:-$FPK_DSH_PORT}`，不要用只在打包脚本里赋值的变量（引号 heredoc 不展开，运行时为空 → status 恒失败）。

生成物静态体检（改动生成物后必跑）：

```bash
python3 - <<'PY'
import io, re
BUILTIN = set(('if then else elif fi for while do done case esac return exit echo cd mkdir rm cp mv '
               'ln tar sed awk grep cut tr date sleep kill pkill pgrep readlink dirname basename cat '
               'head tail sort uniq wc test printf source export local set shift eval exec command '
               'which type id chmod chown touch stat find xargs tee netstat ss curl true false env').split())
def scan(path, start, term):
    L = io.open(path, encoding='utf-8').read().split('\n')
    st = [i for i, l in enumerate(L) if start in l][0]
    en = [i for i, l in enumerate(L) if i > st and l.strip() == term][0]
    gen = '\n'.join(L[st + 1:en])
    defs = set(re.findall(r'^\s*([A-Za-z_]\w*)\s*\(\)\s*\{', gen, re.M))
    calls = set(re.findall(r'(?:^|[;&|(]\s*|\$\(\s*)([A-Za-z_]\w*)\s', gen, re.M))
    calls |= set(re.findall(r'^\s*([A-Za-z_]\w*)\s*(?:\|\||&&|;|$)', gen, re.M))
    assigned = set(re.findall(r'^\s*([A-Za-z_]\w*)=', gen, re.M))
    bad = sorted(c for c in calls if c not in defs and c not in BUILTIN and c not in assigned)
    print('%-32s 生成物 %4d 行；未定义调用: %s' % (path, len(gen.split('\n')), bad or '（无）'))
scan('build/FPK/pack-fpk.sh', 'cat > "$FPK_SRC/cmd/main"', 'EOF')
scan('build/SPK/pack-spk.sh', 'cat > "$ASSEMBLE/scripts/start-stop-status"', 'SSS_EOF')
PY
```

输出里只剩 `break` / `continue` 这类 shell 关键字误报即为干净；出现其它名字就是真缺定义。同类检查：生成物里出现的 `${FOO}` 若只在打包脚本赋值，运行时即为空，必须改运行时来源或给默认值。

## 7. `dsh` / `pnpm` 软链三通道

DSM 安装时可能不执行 installer hooks，单靠 postinst 会失效，故建 `/usr/bin/dsh` 软链走三条通道：

1. installer hooks（postinst / prereplace / postupgrade）统一 `setup_pkg_env`：建版本目录 + chown + 建软链；
2. 远程安装脚本装完以 root `ln -sf` 补建（最可靠）；
3. `start.sh` 启动时幂等重建，回退链 `/usr/bin` → `/usr/local/bin` → `$HOME/.local/bin`（先建父目录；服务以套件用户跑，系统目录不可写时落到套件 HOME）。

## 8. 运行期约定

| 约定 | 要求 |
|---|---|
| `DSH_HOME` | 服务侧强制 `export DSH_HOME="<PKG_VAR>/<版本>/.dsh"`；`dsh` wrapper 注入同一值，用户已 `export` 则尊重不覆盖 |
| PID 文件 | 不放 `/tmp`（fnOS 的 `/tmp` 无 sticky 位、应用用户无权限）；落 `<数据父目录>/<APP>.pid` |
| 临时目录 | 优先平台自带按应用目录：飞牛 `$TRIM_PKGTMP` / `/var/apps/<app>/tmp`（实为 `/vol2/@apptemp/<app>`），群晖 `/var/packages/<app>/tmp`；顶层只选路径不建目录（`check` 等只读子命令必须真只读），建目录留给 `ensure_pid_dirs` |
| 登录 shell | `[ -x "${SHELL:-}" ] || export SHELL=/bin/bash`，保证侧边栏终端可用；不改 `/etc/passwd` |
| 卸载语境 | SPK 的 `preuninst` 置 `DSH_UNINSTALLING=1`；FPK 的 `uninstall_init` 写标记文件 `<数据目录>/.uninstalling`（跨进程只能靠文件），`install_init` 清掉 |
| 判活 | `status` 退出码 0=运行 / 3=未运行；进程匹配用 `pgrep -f "<绝对路径>/bin/start.sh"` 精确匹配 |
| 端口读取 | 脚本与代码不写端口字面量，一律 `read_ports <system>` 读 `build/build-config.yaml` |

## 9. 反代行为约定

请求处理顺序（改动判定时同步更新本文）：

```
⓪ 局域网硬闸 isLoopbackOrLan(ip)   非私网段 → 403 中文提示页（先于一切认证）
① URL 自带 token                   直接放行（套件门户入口走这条）
② 已持 dsh-auth cookie             透明放行（认证过即免密）
③ 门户打开兜底                     302 到带 token 的 URL（cross-site + 同主机 Referer / iframe / 无 Referer）
④ 地址栏直连                       403「请从套件图标打开」（Sec-Fetch-Site: none / 异主机 Referer）
```

必须守住的三条：

- **③ 必须排在 ④ 之前**。fnOS 套件打开与地址栏直连都发 `sec-fetch-site: none`，无法区分；403 在前则从图标打开必吃 403。门户入口 URL 无条件携带当次 token 正是要绕开这个请求头。
- **不得对无凭证的任意请求无条件附加 token**（等于开放无鉴权访问）；**不得删除入口收敛判定**（否则直连也免密）。入口收敛只对文档级导航（`Sec-Fetch-Dest: document/iframe/frame`）设卡，页面内 XHR/WS 放行。
- **陈旧 token 要兜底**：非当次 token → 302 换成当次，否则每次重启后带旧 token 的图标入口打不开。

配套：`SameSite=Strict → Lax` 改写（DSM https→http 跨 scheme，Strict 会丢 cookie 导致无限 302）；401 兜底自动重认证；每次请求 REQ/RESP 记 `<数据父目录>/dsh-proxy.log`。

## 10. 出包前必跑的两个守卫

```bash
./scripts/check-packaging-invariants.py                     # 打包不变量（每项都做过反向验证）
./scripts/check-packaging-invariants.py --verbose           # 列出每条检查内容与结果
./scripts/check-package-parity.py <基准包> <候选包>          # 与安装成功过的包做结构比对
./scripts/check-fpk-payload.py <fpk路径>                     # app.tgz 不含软链、权限合规
```

`check-package-parity.py` 检查：外层条目/钩子缺失、FPK 载荷含软链、`links.tar` / `links.txt` 里的悬空软链（即运行时必缺包）、manifest 字段差异。其悬空判定对 SPK 只作提示（官方基准包自身也有同形态链且正常）。不变量与守卫的对应关系以 `--verbose` 输出为准，不在本文重复列举。

## 11. 真机验收判据

### FPK 全新安装八条

1. `appcenter-cli status <app>` = running
2. 三端口全监听（`ss -ltn` 数到 3 个）
3. 启动日志 0 条 `failed to import` / `did not activate` / `never started`
4. 门户 `ui/config` 与包内原版一致（`url` 为 `/`、`icon=images/icon_{0}.png`、键与 manifest 一致）
5. `cmd/main status` 退出码 0（平台判定不失败）
6. 数据目录无 `tmp/`
7. `TMPDIR` 指向平台按应用临时目录
8. 断链 0 条，且顶层/提升/包内三层链接的关键依赖（`commander`、`js-yaml`、`@deepseek-ai/cordis`、`@szmarczak/http-timer`、`get-stream`）全部可解析

### SPK

启动、反代端口可达、门户免密跳转正常、`dsh` / `pnpm` 命令可用、DSM 桌面图标可点开。

### 启停逻辑改动后

```bash
# 平台判定（决定性）：重启前后 error 10330 计数不增加
B=$(grep -ac "start app error" /var/log/trim_app_center/error.log)
appcenter-cli stop <app> >/dev/null; appcenter-cli start <app> >/dev/null
A=$(grep -ac "start app error" /var/log/trim_app_center/error.log)
[ "$B" = "$A" ] && echo "✓ 无新增启动失败" || echo "✗ 又失败（看 error.log 尾部）"

# 生成物自判
TRIM_APPDEST=/vol2/@appcenter/<app> TRIM_PKGVAR=/vol2/@appdata/<app>/<ver> \
  /var/apps/<app>/cmd/main status          # 期望「✓ 服务运行中」且 rc=0

# 模拟套件打开（无 token、无 cookie）
curl -sL -c j -b j -o /dev/null -w '%{http_code}\n' \
     -H 'Sec-Fetch-Site: none' -H 'Sec-Fetch-Dest: document' -H 'Accept: text/html' \
     http://<NAS-IP>:3080/                 # 期望 200（跟随时必须带 cookie jar）
```

不带 cookie jar 的 curl 会看到 302/303 自循环，那是 curl 不存 cookie，不是服务问题。

## 12. 同版本覆盖安装的坑

应用已装、再 `install-fpk` 同一版本号的包时，fnOS 保留已有应用目录只做增量，**新包里多出来的文件不会被拷进去**（判据：应用体 `.pnpm` 目录数仍是旧的、`bin/start.sh` 仍是旧版，而 `appcenter-cli check` 照样显示 Installed）。

处置：从 Web UI 卸载后重装（CLI 卸载被拒绝）。装前确认 `appcenter-cli check <app>` 是 `Not Installed`、应用目录已清。

应急修复（仅在无法卸载重装时，不动数据、可重复执行）：

```bash
AD=/vol2/@appcenter/<app>/node_modules            # 应用体的 node_modules
zcat x.fpk | tar -xOf - app.tgz > /tmp/a.tgz && mkdir -p /tmp/a && tar -xzf /tmp/a.tgz -C /tmp/a
# ① 补齐缺的 .pnpm 实体（只补缺，不动已有）
for d in /tmp/a/node_modules/.pnpm/*/; do n=$(basename "$d"); \
  [ -e "$AD/.pnpm/$n" ] || cp -a "$d" "$AD/.pnpm/"; done
# ② 三层链接补齐 + 纠正错链（用打包脚本同一份实现，幂等）
python3 build/fix-node-links.py /vol2/@appcenter/<app>
# ③ 重启（走平台自己的路径，便于直接看 error.log 有没有新增 10330）
appcenter-cli stop <app> && appcenter-cli start <app>
```

## 13. 数据隔离（新增实例 / 改包名时）

| 约定 | 要求 |
|---|---|
| 数据区 | 每个实例的数据只在 `<本应用数据目录>/.dsh`，进程 spawn 时显式把 `DSH_HOME` 指到该位置 |
| 共享区 | 不把数据目录硬切到 `@appshare` 的共享目录；`build/build-config.yaml` 的 `defaults.share_workspace_dir` / `share_data_dir` 默认留空 = 不创建任何共享目录（零副作用），需要时再填目录名 |
| FPK `config/resource` | 不带 `data-share` 段（除非该应用确实需要共享目录）。带它会让安装器把本应用 data 软链到共享区，连带把其它实例的 profile 目录卷进来 |

装完新实例后立刻核验有没有把软链写进别的实例：

```bash
find <其它实例数据目录>/.dsh/profiles -type l | xargs -r readlink | grep -c <新app名>     # 期望 0
```
